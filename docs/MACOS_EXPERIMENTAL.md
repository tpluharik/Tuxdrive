# Experimental macOS package

TuxDrive 0.16.0 includes an experimental macOS application/package build for Apple silicon. It is intended for development and compatibility testing, not production deployment. The CI artifact is ad-hoc signed, not signed with an Apple Developer ID and not notarized.

## Host requirements

- macOS 13 or newer on Apple silicon
- Homebrew
- Homebrew Python, GTK 3, PyGObject and the Adwaita icon theme
- optional macFUSE for experimental files-on-demand mounts
- optional Homebrew packages for Tor, obfs4, NAT traversal and QR functions

Install the graphical runtime before opening the application:

```bash
brew install python@3.12 gtk+3 pygobject3 adwaita-icon-theme
```

Download the `tuxdrive-macos-experimental` artifact from the GitHub Actions run and install its `.pkg`. Because the package is not notarized, macOS may block first launch. Do not bypass organizational Gatekeeper policy; development machines can inspect the package and explicitly approve it through Privacy & Security.

## Native adaptations

- OAuth and online folders open through macOS `open`.
- The encrypted rclone configuration key is generated locally and stored through the macOS Keychain Security framework. It is never passed to the `security` command or placed in process arguments.
- Login startup uses `~/Library/LaunchAgents/io.github.tuxdrive.TuxDrive.plist`.
- The verified bootstrap downloads the pinned rclone macOS arm64 or amd64 archive and checks its release SHA-256 digest.
- Configuration, cache and log paths follow `~/Library/Application Support`, `~/Library/Caches` and `~/Library/Logs`.
- macFUSE streaming uses the native `umount` path; kernel-extension approval and a reboot may be required.

Run the capability report from Terminal:

```bash
/Applications/TuxDrive.app/Contents/MacOS/tuxdrive --system-check
```

## Missing or limited functions

- No Finder badges, context menu, offline pinning UI or Finder extension. Nautilus integration remains Linux-only.
- The package is not self-contained: Homebrew supplies GTK/PyGObject.
- No notarized automatic updater; install newer experimental packages manually.
- Metered-network detection is Linux/NetworkManager-only.
- Tray behavior follows GTK's macOS integration and is not equivalent to the GNOME AppIndicator implementation.
- Intel builds are code-supported by the rclone bootstrap but are not currently generated by the default Apple-silicon CI job.
- Real provider OAuth, Keychain lock/unlock, sleep/wake, macFUSE and large-tree testing must be completed on physical macOS hardware before promotion beyond experimental status.

## Build locally

On a prepared macOS host:

```bash
sh scripts/build-macos-pkg.sh
```

The output is `dist/tuxdrive_0.16.0_experimental_macos_<architecture>.pkg`. Production distribution requires Developer ID Application/Installer signing, hardened runtime review and Apple notarization.
